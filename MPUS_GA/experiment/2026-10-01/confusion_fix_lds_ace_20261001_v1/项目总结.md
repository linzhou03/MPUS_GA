## 🎯 项目目标

针对 CAGA-SGA 论文 Figure 4 观察到的**系统性混淆偏差**（"Positive 吸引子"现象），设计并验证三类改进方法：

1. **非对称混淆损失（asy）**：重点惩罚容易误判为 positive 的样本
2. **增强偏置校准（cal）**：利用多尺度证据校正类别预测偏置  
3. **Confusion-Aware CBST（cbst）**：伪标签选择时考虑混淆风险

通过 8 种配置（baseline + 7 种组合）在 ACE 三方向上进行消融实验。

## 🔧 技术架构

### **数据流**
```
LDS 数据 (519 NPZ)
    ↓
R4 编码器（1s/2s/4s 独立）
    ↓
【cal】校准器（300步后） → 校准后的尺度 logits
    ↓
类别条件融合 → 融合 logits
    ↓
【cbst】CA-CBST 选择 → 高质量伪标签
    ↓
【asy】非对称损失 → 惩罚危险 positive
    ↓
源域 CE + 目标伪标签 CE + 域对抗 + 非对称损失
```

### **关键时间点**
- **0-300 步**：源域 warmup，校准器收集源域混淆统计
- **300 步**：冻结混淆矩阵，启动校准和 CA-CBST
- **301-1000 步**：完整训练，post300_bal_best 选优

### **8 种配置的消融逻辑**
```
baseline (对照)
    ├─ asy (单独测试损失)
    ├─ cal (单独测试校准)
    ├─ cbst (单独测试伪标签)
    │
组合测试：
    ├─ asy_cal (损失 + 校准)
    ├─ asy_cbst (损失 + 伪标签)
    ├─ cal_cbst (校准 + 伪标签)
    └─ full (三者全开)
```

## ⚠️ 关键风险与应对

### **风险 1：集成时遇到兼容性问题**
**症状**：`train_cbst.py` 的现有逻辑与新模块冲突

**应对**：
- 先用最简单的配置（baseline）验证流程
- 逐个模块添加，每次验证
- 保留原始 `train_cbst.py` 备份

### **风险 2：效果不明显或变差**
**症状**：改进配置的 BalAcc 低于 baseline

**应对**：
- 检查模块是否真的被调用（加日志）
- 分析诊断信息（每个模块都返回 diagnostics）
- 调整超参数（threshold, strength, momentum）
- 尝试单模块组合，找出"害群之马"

### **风险 3：实验时间超出预期**
**症状**：每个 fold 超过 8 小时

**应对**：
- 优先跑 baseline 和 full，看两端对比
- 如果资源紧张，跳过部分组合配置
- 考虑降低 max_iters（如 1000 → 800）
